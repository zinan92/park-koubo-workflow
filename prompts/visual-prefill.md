# 视觉选型与画面预填 · v1

用于每次新视频默认预填及后续视觉重设计。先读原话、前后语境、原画面和用户笔记，再读 ShotCraft 卡与准确 demo。不要先挑漂亮卡片再找句子填进去。Hook 仍使用 hook-prefill.md，原有用户选择不得覆盖。

## 每个点先回答四个问题

1. `takeaway`：观众应该理解的具体意思是什么？
2. `relation`：表达的是数量比较、分配守恒、变化、两个维度、因果、流程、反馈，还是一句判断？用具体短语，不限制为封闭枚举。
3. `form` / `reason` / `alternative` / `alternative_reason`：采用什么结构，为什么？比较一个有意义的替代方案（可为保留原画面），说明取舍。相同关系允许相同形式，不为凑多样性硬换图。
4. `motion_meaning`：观众看到哪个对象发生什么变化，从而理解什么？静态内容说明为何无需动画。单纯淡入、弹跳、换皮不算语义解释。

这些答案写在每个 shot 的 `design` 中。用 `animated` 布尔值在计划阶段明确是否实际制作动画；预览索引的 motion 必须与其一致，不能在出图阶段改为静态免交样片。另用 `state_change` 布尔值声明理解是否依赖前后状态对照；true 时必须提供两张不同时刻的合成图，一张在 reveal 前，一张在 hold 后。不是所有动效都必须做两张图。

## 选型依据

| 要表达的关系 | 可考虑的形式 | 约束 |
| --- | --- | --- |
| 记住一句判断 | 文字重点 | 文案简洁，视觉没有额外解释价值就不硬加图 |
| 类别数值大小 | 条形图 | 共用尺度与基线，标签和几何同源 |
| 样本分布 | 直方图 | 有真实样本与分箱依据，不能把任意柱状图叫分布 |
| 随时间或变量变化 | 曲线 | 数据有来源；概念示意明确变量及含义，不伪造走势 |
| 总量不变、集中或分配 | 单位点阵重组 | 同一批对象，单位与总量守恒 |
| 两个不同维度 | 矩阵 | 轴含义明确；格子面积不冒充概率 |
| 顺序、边界、重复与间隔 | 事件时间轴 | 下一周期起点要可见，横轴不要暗示未经提供的实际时长 |
| 结果影响下一次行动 | 反馈回路、对象更新 | 返回路径必须进入决策对象，更新后再执行，不能只是三个词转圈 |
| 拆解构成或条件触发 | 分支、分层展开、条件门 | 用实际维度/条件，不编造数量或结果 |

表格是候选，不是限定菜单。先决定结构，后选 ShotCraft 的运动语法；图形仍必须实际用 React/Remotion。复用准确 demo 时保留有意义的动作，删除不适用于本内容的模板标签/装饰。无合适卡可用有理由的 React/SVG 定制结构，按 remotion-execution.md 留证。

## 全片检查与预填交付

按 `design.form` 浏览全片。重复形式须在 plan 的 `form_reuse_reason` 说明为何同样关系适合重复；不要设置“必须用几种图”的配额。判断每个动作是否增加信息，原画面更清楚就保留原画面并记录 note disposition。

制作 Agent 负责选型与真实样片；一个不同 session 的独立 reviewer 负责表达与实际输出两类 QA；Park 只需看画面给选择。选型文字默认留在折叠详情，不增加用户逐条文字审批。

每个保留视觉点提供同一时间的原画面/合成画面对照；状态变化提供开始/落定。代表样片覆盖不同主要结构与风险，不能用一支卡片动画代表矩阵、点阵、时间轴和反馈所有形式。正常速度带原声审核；静音探索示例必须标明范围，不能作为正式预填/H2动效验收。

默认 prefill 包含选型、真实画面与独立预审。早期先交文字时只能标“规划草稿”，不能称预填完成或请求视觉批准。复用将用于正式制作的同一工程，禁止另画不可执行的理想稿冒充实现。保持工作台 Hook/visual 的增删改及 Hook 排序。

## 独立审核

先核验各 design 决策与原话，再看全部真实图和代表样片。`semantic_selection` 检查表达结构、动作的信息增量、替代方案与重复形式理由；`output_integrity` 检查实际数值/比例、方向、可读性、遮挡及中途丢元素。每项证据注明 shot 和时间/帧号；记录实际观看范围。现有 usefulness/composition/pacing/reference_quality 继续保留。

发现错误退回制作，重出受影响预览并独立复查。不能用像素稳定测试代替正常速度观感审核。专用 Remotion Headless Shell 应优先于日常浏览器；出现随机漏绘时检查真实逐帧输出、渲染配置与浏览器匹配，不把源码正确当成成片正确。

所有 design、prompt、来源、工程、截图、样片都进入现有哈希证据链。变更使关联 QA/H2 失效；已批准的 Hook 不因此重做。脚本检查证据完整性，无法证明 Agent 真正思考或保证审美；独立审核与用户画面选择仍必要。不增加全局系统 hooks 或额外用户审批门。
